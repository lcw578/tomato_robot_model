### 2.2 事件触发主流程（对应论文 Figure 9 控制流程图）

1. **行进+检测**：主控订阅彩色+对齐深度帧（`message_filters` 同步，slop=0.1s），逐帧调 YOLO 服务；`processing_lock` 防重入。
2. **检测到可采番茄 → 停车**：`classify_detections` 分出 stem/tomato/trunk → `combine_boxes` 茎果匹配（先按 IoU（以 stem 面积为分母），失败再按"平移 15% 图像尺寸可相交"次选，且要求 stem 底边高于番茄中心）→ 首次出现匹配对时通过 `SetParameters(is_continue_run=False)` 令底盘停车，清空缓存等新帧。
3. **停车后重新定位**：缓存最多 5 帧做时域深度平均；`after_stop_try_times > 5` 次仍无匹配则强制恢复直行（对应论文"两次尝试失败继续前进"的工程化版本）。
4. **逐串采摘**（无显式排序，按检测顺序）：对每个匹配对——骨架法判生长方向 + 定采摘点像素 → 三级取深度（直接像素 → 45px 邻域 → 5 帧时域，有效域 0.20–1.0 m）→ 反投影 + 左/右手眼矩阵变换到 Aubo 基座系 → 可达性过滤（距离 ≤ 0.784+0.10 m，Z ≥ 0.25 m）→ 生成位姿（rx=90°，ry=±70° 限幅，rz 按 Y 正负取 0/180°）并按夹爪长度 0.10 m 和生长角补偿 → 发 `move_to_pose`。
5. **机械臂三点路径**（对应论文 SI §2）：初始点（关节角 [10.32, 15.37, 134.05, 117.05, 86.63, 0]°）→ 内缩位 → 过渡点 C（目标点沿果梗反方向退 0.1 m，到位发 `midpoint_reached=true`）→ 5 个细分直线过渡点、以 5°/s + 0.01 m/s 慢速逼近采摘点 B。
6. **闭环确认**（robot_2_launch 闭环模式）：到达过渡点后，手腕相机在夹持传感器上升沿触发近拍，YOLO 分割 + 骨架/距离变换测直径（阈值 10 mm，4.865 px/mm），发 `test_result`：2=果梗（安全）→ 主控令夹爪 close（丝杠推到位=同时剪切+夹持）→ `return_to_box` 倒序退出回果箱上方 → gripper open 释放番茄入筐；3=主茎（危险）→ 不下刀。
7. **失败重试**：`result==0` 但未检出果梗，或 31004 碰撞错误 → `target_return_midpoint` 退回过渡点，按 x+0.02 → x−0.02 → z+0.02 → z−0.02 十字偏移重试，最多 4 次；超限 `return_to_box` 放弃该串。逆解/运动失败（30001–30007）→ `move_joints` 回初始位。
8. **视区内采完 → 恢复直行**；**RFID 卡 13/23（作业行出口）→ 相机热切换**：读 `/tmp/realsense_camera.pid` SIGTERM 杀旧相机 + 按 `__node:=camera` pkill 兜底 → `Popen` 启动另一侧 launch → 重取内参、换用对应手眼矩阵。之后反向采收另一侧，直至路线完成。

### 3.2 `vision_packages` —— 分割式感知服务链（新一代）

```
cam_hand RGB-D → image_preprocess_node(中心正方形裁剪+内参修正) → detection_service(YOLO11s-seg)
                                                              → pose_estimator_service(骨架+切线)
pick_pose_service_node：串联两个服务，统一入口 /vision/tomato/get_pick_poses
```

- **模型**：`yolo11s_seg_peduncle_cluster_0601_640_best.pt`（YOLO11s-seg，640 输入，conf 0.35，iou 0.5，cuda:0），三类实例分割：`peduncle`（果梗）/ `tomato_cluster`（果串）/ `tomato_fruit`（单果）。
- **采摘点确定**（替代论文的 k-means+形态学+Zhang-Suen）：果梗最大连通域 → 3×3 闭运算 → `cv2.ximgproc.thinning` 细化 → 8 邻域找端点、选离果串质心最近端点为起点 BFS 排序骨架 → 取**骨架中点**为采摘点。
- **3D 切线**：采摘点半径 18px 内骨架点 ≥4 个时，对 3D 点做 SVD 第一主成分拟合，失败回退 2D 切线；姿态用 Gram-Schmidt 正交构造（`tool_y`=果梗切线）。
- **深度四级降级**：直接像素 → 局部窗口中值 [7,11] → 果梗掩膜中值 → 果串掩膜中值（[7,11,15,21]），来源记入 `reason` 字段。
- **成熟度估计**：HSV 分红/橙/绿比例，`red_ratio>0.55 → ripe`，参与候选评分。
- **候选评分**：`0.35×果梗置信度 + 0.25×果串置信度 + 深度有效 ± + 骨架点数奖励 + 成熟度奖励 − 配对距离惩罚 − 截断惩罚`，只返回最高分。
- `vision_tomato_interfaces`：`InstanceMask / PickPoseCandidate / GetPickPoses` 等自定义接口。`vision_pose_generate_client` 是空格键触发的交互调试客户端（OpenCV 三面板 + 可选 Open3D 点云）。
- 注意：**手眼变换不在本包**（`hand_eye_enabled: false` 且代码未使用），本包只输出相机系位姿；相机→基座由主控左乘标定矩阵完成。

### 3.3 `closed_loop_feedback_detection` —— 切割区闭环防误切（论文未来工作已落地）

- **触发链**：`midpoint_reached=true`（机械臂到过渡点）+ `gripper/input_x1_status` 0→1 上升沿（夹持区果梗传感器）→ 订阅 `/cam_hand/*` 同步帧推理 → 发布 `test_result`（0=初始化，1=传感器触发，2=果梗，3=主茎），连发 10 次×0.1s。
- **防误切判定**：ROI 左右各涂黑 1/4 保留中间 1/2 → YOLO 分割（`gripper_stem_xiongAn_20260726.pt`，conf 0.5/iou 0.2）+ 距离变换测直径：3×3 闭/开 → `distanceTransform(L2)` → GuoHall 细化 → 保留最大骨架分支 → 沿骨架取 `直径=2×距离变换半径`、截断均值（去两端 15%）→ **直径 >10 mm 判主茎（危险）**；YOLO 类与计算类任一为 trunk 即危险；`pixel_per_mm=4.865`，冷却 1.5s，最多采 5 帧。失败兜底 `minAreaRect` 短边。
- 这正对应论文结论中"camera detects the diameter of plant material entering the end-effector cutting area"的反馈机制设想——代码已实现并接入主控决策。

### 3.4 `xc_aubo_arm_control` —— 机械臂运动服务（C++）

- **核心** `motion_service.cpp`（1341 行）+ `auboi5_path_check.cpp`（746 行，Bullet 碰撞检查），节点 `aubo_motion_service`。
- **与控制柜通信**：Aubo SDK v2.5.0（`lib/libaubo_sdk.so`），TCP `192.168.1.5:8899`，账号 aubo/123456；节点内 3 条独立连接（运动/返回/状态），运动前 `rootServiceRobotStartup`。
- **服务**：`move_to_pose`（含 `mid_to_target` 仅过渡点→目标、`start2mid` 两段式、`mid2target_angle` 接近角）、`return_to_box`、`target_return_midpoint`、`move_joints`；20ms 发布 `arm_status`；发布 `midpoint_reached` 与工具 DI 口 `gripper/input_x1_status`。
- **路径规划**（论文 SI §2 的三点法）：过渡点 = 目标沿果梗反方向退 0.1 m → `robotServiceRobotIk` 逆解（失败 ±0.01m 扰动重试 ≤20 次）→ 接近段细分为 5 个直线过渡点 → 关节运动到内缩位/过渡点后慢速（5°/s、0.01 m/s）逐点逼近，末端 `SetNoArrivalAhead`，前段 `ArrivalAheadDistanceMode(0.02)` 提前换向。返程按去程 waypoints **倒序**关节退出 → 内缩位 → pick_start → 初始点（果箱上方）。
- **姿态**：RZ 叠加 `mid2target_angle`（归一 ±90°）；完全朝前生长（±90°）改 RX=150° 从上往下剪；目标在身后时关节 5 取 ±33° 摆位（论文 ±30° 的实现）。工具 TCP 偏移硬编码 `(-0.0011, -0.0013, 0.0573) m` 写入 SDK。
- **安全**：URDF 关节限位 + Bullet 自碰撞/障碍物（果箱 23×30×14 cm 与立柱 7×11×41 cm 两个 box），**去程+返程全轨迹二次校验**后才动作；关节 1 按 Y 正负限制 [10°,370°] / [−350°,0°]。
- **错误码体系**（`说明.txt`）：30001–30007 各段逆解/运动失败，31001–31004 各段碰撞失败；`10023` 视为成功。
- 仿真/测试：`aubo_description`（URDF+mesh，gripper_cam 模型）、`fake_joints/*.txt` + `fake_picking` 轨迹回放、`continuous_motion_client`。

### 3.5 `gripper_driver_v2` —— 末端执行器驱动

- **硬件通道已从 CAN 切到 RS485/串口**：当前 `gripper_control_node.py` 用 `Gripper485Driver(port='/dev/ttyACM0')`；CAN 版（`gripper_can_driver.py` + `setup_can.sh` slcand/socketcan 1 Mbps + systemd `can-config.service`）保留备用。
- **协议**（类 Modbus-RTU）：帧头 `FF FF FD 00` + ID + Len + 指令 + CRC16；扭矩使能写 0x0202=1；目标位置寄存器 **532 (0x0214)** 4 字节小端；读实际位置 0x0228；读电流寄存器 546（堵转/剪切力判断用）。
- **动作语义**（单电机丝杠，推到位=剪切+夹持同时完成，回退=松开）：`open` = −4096（完全回退），`close` = −1838（试验位）/ −1638（真剪断位，注释保留）；超时 5s、容差 5 脉冲。服务 `gripper/control`（open/close → success + current_position + message）。
- `gripper_fake_node` 供仿真联调；`can使用方法.txt` 含实测帧日志。

### 3.6 `xc_car_control` —— 底盘与导航

- **串口**（`agv_control_node.py`）：115200-8N1 `/dev/ttyS0`；帧 `0xDE 0xED | 0x16 | 命令码 | 16B 数据域 | 2B 校验和`；命令 0x02 控制（直行/旋转速度 i16 限幅 ±1200 mm/s、超声刹车 250 mm、磁条传感器升降）、0x01 状态请求；状态帧解析电池电压（0.1V）、错误位、**bit3/bit4 前/后磁条传感器、bit13 升降状态、字节 8-9 RFID 白卡号**、左右轮速。10Hz 定时器发布 `agv_status`；服务 `control_agv`；参数 `is_chassis_running` 可全局暂停。
- **导航**（`agv_navigation_node.py`）：按 `navigation_file/navigation_file.csv` 的 `卡号,动作码` 序列执行，动作码 1–6 = 传感器降/升 × 前进/后退 × 左转/右转。直行每 0.1s 发 100 mm/s，**到卡判定 = white_card_id 等于下一指令卡号**；原地转向先 2s 起步再 0.03s 重发转速，**直到磁条传感器压线**（对线）；脱线 20s×3 次警告后停车。卡号编码 = 行号×10 + 行内点位。
- **作业行七连**（UI 生成）：`x1,5 左转 → x1,1 前进 → x2,3 升传感器进轨道 → x3,4 升传感器后退返回 → x2,2 降后退 → x1,6 右转 → x1,1 前进离行`——与论文"进轨道采完一侧、反向采另一侧、回到起点换行"的作业流程一致。
- **简化导航**（真机 launch 实际使用）：`agv_always_go_straght(_only).py` 直行至末端卡（43/23）自动反向，主控通过参数 `is_continue_run` 控制其启停——即"视觉事件触发的走走停停"。
- `param_setter_node`（暂停辅助）、`vis_car_control_node`（残缺测试桩）。

### 3.7 `tomato_robot_ui` —— Qt 上位机

- `ament_cmake` + Qt5 Widgets + OpenCV + rclcpp；`rclcomm : QThread` 内嵌 rclcpp 30Hz `spin_some`；图像信号槽 `Qt::DirectConnection`。

### 4.3 代码与论文不一致 / 论文有而代码无

1. **相机型号**：论文 RealSense L515（α=14° 参数化布置、70×55° 视场）；开发版代码用 **D435 ×2**（序列号 f1150496/f1422449）+ 手腕 D435——相机内参 fallback 也是 D435 值。参数化布置的结论（α=14°、x0=310 mm）体现在左右分置 + 倾斜安装的实物上，代码层面无对应计算。
2. **采摘顺序**：论文 §3.2.2 明确"按 X 降序、再按 Z 降序排序"；代码**没有显式排序**，按 YOLO 检测输出顺序逐串发送（`detection_callback` 内注释掉的排序痕迹未启用）。这是行为差异，可能与论文描述的样机版本不同。
3. **升降平台**：论文 3.1.1/Figure 3 有独立 STM32 控制的升降平台模块（UI 设定高度）→ 本工作空间**无任何对应代码**（协议中的 `lift_magnetic_sensor` 只是磁条传感器支架升降，不是平台升降）。
4. **UI 功能**：论文 Figure 8 的 UI 模块含参数设置与数据检索 → 代码仅作业行设置 + 图像显示。

## 5. 已知问题与建议

1. **Bug**：`xc_robot_main_control_node.py` L2155/L2176 使用未定义变量 `pid_file`（应为常量 `PID_FILE`），相机热切换第一分支会抛 NameError——目前靠 `kill_nodes_by_ros2_node_name` 兜底未影响功能，但建议修复。
